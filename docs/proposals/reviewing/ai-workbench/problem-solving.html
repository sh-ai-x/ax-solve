Decision

AI 업무 해결 워크벤치를 개인용 웹 도구로 만든다.

핵심은 사용자가 비정형 개발 문제나 업무 자동화 요청을 입력했을 때, 이를 곧바로 코드나 답변으로 바꾸는 것이 아니라 다음의 검토 가능한 작업 단위로 변환하는 것이다.

  1. 문제와 맥락을 한글로 정리한다.
  2. goal, constraints, success criteria, anti-goals, acceptance rubric을 채운다.
  3. 실행 단계와 분기를 workflow로 만든다.
  4. Archify로 흐름을 시각화한다.
  5. Claude/Codex가 실행할 수 있는 handoff를 만든다.
  6. 결과와 근거, 결정사항을 문서로 남긴다.

Problem to solve

AI 도구를 잘 활용해도 업무 요청이 모호하면 프롬프트, 산출물, 검증 기준이 매번 새로 만들어진다. 그 결과 문제 파악, 일정·자료 관리, 팀 커뮤니케이션, 결과 품질 확인이 단절된다.

이 제안은 그 단절을 입력 → 구조화 → workflow → 실행 handoff → 산출물 → 검증이라는 하나의 반복 가능한 흐름으로 만든다. 도구의 사용자는 최종 결과를 승인하는 사람이며, LLM은 근거를 바탕으로 초안과 선택지를 만드는 역할로 제한한다.

MVP workflow

업무 요청/개발 문제
  ↓
5-field 인터뷰와 누락 질문
  ↓
문제정의서 + 제약조건 + 성공 기준
  ↓
workflow 생성 및 Archify preview
  ↓
Claude/Codex handoff 생성
  ↓
Markdown 산출물 + 결정 로그
  ↓
acceptance rubric 검토와 승인

각 단계는 상태와 입력·출력을 갖는다. 사용자는 어느 단계에서든 결과를 수정하거나 이전 단계로 돌아갈 수 있어야 하며, 승인되지 않은 결과는 다음 단계의 확정 입력으로 취급하지 않는다.

Product surface

  • Request workspace: 문제, 목표, 참고 자료, 원하는 산출물을 입력한다.
  • Interview panel: 모호한 항목을 한 번에 하나씩 질문하고 5-field 계약을 채운다.
  • Workflow canvas: 단계, 담당 역할, 분기, 검증 지점을 Archify로 확인한다.
  • Handoff drawer: Claude용 지시서, Codex용 작업 단위, 파일·검증 조건을 복사한다.
  • Evidence log: 생성 근거, 사용자 결정, 승인 상태, 실패한 기준을 기록한다.
  • Export: 문제정의서와 실행계획을 한글 Markdown으로 저장한다.

Technical direction

웹 UI와 도메인 workflow 엔진을 분리한다. provider adapter는 Claude와 Codex의 프롬프트·응답 형식 차이를 숨기고, 도메인 엔진은 특정 모델의 문장 형식이 아니라 계약과 상태 전이를 관리한다.

Archify에는 직접 UI 상태를 넘기지 않고, 검증된 workflow 모델에서 diagram JSON을 생성한다. 따라서 문서와 시각화가 서로 다른 사실을 보여주는 문제를 줄일 수 있다. 모든 LLM 결과에는 원문 근거와 검토 상태를 보존한다.

Acceptance rubric

  • 사용자가 업무 요청 하나를 입력하면 5개 필드의 현재 상태와 누락 질문을 확인할 수 있다.
  • 5개 필드가 채워지지 않은 상태에서는 ready handoff나 승인 완료를 표시하지 않는다.
  • 동일한 workflow가 Archify preview와 Markdown 실행계획에서 같은 단계·분기·검증 기준을 유지한다.
  • Claude/Codex handoff에는 목표, 제약, 성공 기준, 작업 단위, 변경 범위, 검증 명령이 포함된다.
  • 사용자는 LLM 초안을 수정하고 승인 또는 반려할 수 있으며, 결정사항과 근거가 로그에 남는다.
  • 대표 시나리오 3개에서 누락 질문, 잘못된 상태 전이, 근거 없는 완료 표시를 자동 테스트로 잡는다.

Out of scope and rollout

  1. Slice 1 — 문제 해결 vertical slice: 인터뷰, workflow 모델, Archify preview, Markdown 문서, Claude/Codex handoff를 완성한다.
  2. Slice 2 — 운영 품질: 대표 사례 평가셋, 재현 가능한 테스트, 실패 로그와 비용·응답시간 관찰을 추가한다.
  3. Slice 3 — 산출물 확장: 실제 사용 사례가 확인된 뒤 PPTX 또는 XLSX 중 하나를 선택해 exporter를 추가한다.

인증, 사내 데이터 커넥터, 자동 메일 발송, 팀 협업, 다중 모델 라우팅은 MVP의 성공을 흐리는 범위이므로 이번 제안에서는 구현하지 않는다.

Review questions

  • 첫 번째 대표 시나리오는 개발 버그 해결, 반복 업무 자동화, 또는 보고서 작성 중 무엇으로 할 것인가?
  • MVP 산출물 확장 우선순위는 PPTX와 XLSX 중 무엇이 실제 업무를 더 잘 증명하는가?
  • Claude/Codex handoff를 복사·붙여넣기 형식으로 시작할지, 로컬 plugin command까지 바로 제공할지 결정해야 한다.

Score scale: 0 = fully mitigated · 1 = acknowledged + mitigation · 2 = known trade-off · 3 = unmitigated blocker.

  • [1/3] 초기 버전은 개인용이라 다중 사용자·SSO·권한 관리가 없다. 로컬 또는 단일 사용자 배포를 MVP의 명시적 운영 경계로 두고, 팀 배포가 필요해질 때 인증을 별도 단계로 추가한다.

  • [1/3] PPT와 Excel을 동시에 완성도 높게 지원하면 범위가 커진다. MVP는 Markdown·Archify preview·Claude/Codex handoff를 우선하고, PPTX/XLSX exporter는 검증된 workflow 이후의 확장 단계로 둔다.
